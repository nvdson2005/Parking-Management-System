## 1. How to read the matrix

- One row per objective and delivering product. Requirements are those SRS v2.1 section 8.1 traces to the objective, assigned to a product by SRS chapter: 3.1 and 3.8 → P07, 3.2 and 3.9 → P05, 3.3 → P09, 3.4 → P08, 3.5 → P06, 3.6 → P10, 3.7 → P11. NFRs sit on the row of the product they are measured on. A requirement traced to two objectives appears in a row for each.
- Rows marked *baseline link* list a product the baseline traces to the objective even though no requirement of that objective sits in the product's chapter (for example P03 for O1).
- **Activity** and **Resource** come from Baseline V2.0 (`activities[].assign`). Later changes (CR-03, the final work division) are named in Notes.
- **Risk** shows the score from F3-01 (L × I; set 26/11, some rationales updated 27/11 with the scores unchanged), or the state if the risk closed or occurred. Risks are those the baseline (`risks[].acts`) links to the row's activities, plus objective-level risks where the baseline lists them; the full lists per objective are in `generated-v2/traceability.md`.
- **Verification** shows the result, not only the test ID. "Automated" means the run of 382/382 tests on `ac57507` (A-87, F2-04). Test names refer to `tests/` on `main`.
- **Checkpoint** shows the outcome recorded in F2-03. Products with no gate in the baseline say so. The baseline also gives CP-08 (A-88, client confirmation) to every O4 and O5 row; it was not obtained for any of them (client not available, F5-03) and is shown only on rows 20–23.
- **Status** uses the workbook values: *Consistent* (sources agree, nothing open), *Consistent, conditions open* (sources agree, a gate or evidence item is still open), *Inconsistency noted* (see section 4).

## 3. Requirement coverage

SRS v2.1 has 53 FR and 13 NFR (section 8.3).

- **Within the SRS:** I compared the objective column of every FR and NFR row with the table in section 8.1. All 66 requirements trace to at least one objective, and each row's objectives equal those listed in 8.1 (O1 14, O2 15, O3 16, O4 24, O5 7).
- **In this matrix:** each of the 53 FR and 13 NFR appears in at least one row, under every objective 8.1 gives it.
- **Gates:** every row has a verification. P07 and P08 have no checkpoint in the baseline (rows 4, 5, 9, 15, 17); they are checked by A-31, A-61 and the acceptance run (CP-07).
- **R-M3-02 (FR renumbering): two code sets remain, both now labelled.** The SRS is consistent with itself. SRS v2.1 section 8.4 states that P18 keeps the FR codes of the MVP build spec, which differ from the SRS codes. A-31 now writes both (for example "FR-30 build spec = SRS FR-42" for masking, FR-31 = FR-43 for the full-plate log, FR-32 = FR-45 for purge; PR #30), and F3-01 describes the same state (pending #29). This matrix uses SRS v2.1 codes only. A reader who takes a P18 code for an SRS code would still point to the wrong requirement, so the report should say which code set each document uses. Whether R-M3-02 closes when this matrix merges is RES-03's call in F3-01.
