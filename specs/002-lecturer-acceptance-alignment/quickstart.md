# Phase 5 Validation Quickstart

1. Verify the latest `origin/main` and GitHub PR bases and heads. Choose an acceptance SHA containing both product changes and write down whether it is merged or an integration candidate.
2. Use a disposable SQLite database. Set `DATABASE_URL` to that file, then run `npx prisma migrate deploy` and `npm run db:seed`. Verify the migration chain and schema against the candidate. Run `npm test`, `npm run lint`, and `npm run build` before the production-build rehearsal.
3. **AT-03 / A-61** — Save informational hours as Manager. Confirm Customers can view them and ordinary rules still govern entry and reservations. Configure different motorcycle and car rates for two groups. Verify both Customers see their own rates. Confirm a Customer can request a group change, only Manager can apply it, and the existing permission checks still pass.
4. **AT-04** — Exercise Staff and Manager over the closed-session list, detail and relevant responses. Include a short plate. Verify Staff sees masking and Manager sees the full retained plate. Verify automatic purge uses exit time, retains a session with old entry and recent exit, and preserves historical counts, durations and revenue. Confirm unrelated event notes survive the purge.
5. **AT-01 / AT-100 and exceptions** — Correlate each recorded entry or exit with its browser update. Verify ≤3 s recording and ≤5 s display latency, complete closed records and exact manual availability counts on the normal 100-visit scenario. Record all five exception outcomes, including a separate full-lot refusal. Check core workflows at 360, 768 and 1920 px on Chrome, Edge and Firefox.
6. Record actual timing, count, browser version and width, outcome, tested SHA, and evidence link. Carry exclusions and open defects into P14, QA's verdict into the gate record, and the lecturer's acceptance outcome into A-89.
